# 0003 — `fifth_sub_eq_of_add_eq`

> 本文書は日本語正本です。英語版は本正本からの対応翻訳です。

## Lean の宣言

```lean
theorem fifth_sub_eq_of_add_eq
    {x y z : ℕ}
    (hEq : Fermat5Equation x y z) :
    z ^ 5 - y ^ 5 = x ^ 5 := by
  unfold Fermat5Equation at hEq
  omega
```

完全修飾名は `DkMath.FLT.Five.fifth_sub_eq_of_add_eq` です。

## 数学的主張

仮定 `hEq` は指数5のフェルマー方程式

$$
x^5+y^5=z^5
$$

を表します。この補題は、その加法形を

$$
z^5-y^5=x^5
$$

という差分形へ移します。

通常の整数環では単なる移項ですが、ここで扱う型は自然数 `ℕ` です。Lean の自然数減算は切り捨て減算なので、一般には加法の項を無条件に反対側へ移せるわけではありません。この補題では元の等式自体が `y ^ 5 ≤ z ^ 5` を保証するため、差分形が正しく成立します。

## 証明全体での役割

この補題は、最初の方程式インターフェースから gap 因数分解へ向かう変換橋です。

後続では `z ^ 5 - y ^ 5` を、自然数の gap `z-y` と `GN5 (z-y) y` の積として表します。したがって、元の反例方程式から

$$
x^5=(z-y)\,\mathrm{GN5}(z-y,y)
$$

という積構造へ進むには、まず左辺を差分の第五冪として露出させる必要があります。

この補題単独ではまだ `z-y` を導入しません。しかし、加法形を後続の差の冪の因数分解へ接続できる形に整える、最初の代数的正規化を担当します。

## 直接依存する定義・補題

プロジェクト内で直接依存する宣言は次の一つです。

- `DkMath.FLT.Five.Fermat5Equation`

証明処理としては次を利用します。

- `unfold` による定義展開
- `omega` による Presburger 算術処理
- 自然数の加法、冪を固定項として含む等式、自然数減算

注意すべき点として、`omega` は冪そのものを非線形算術として展開しているのではありません。ここでは `x ^ 5`、`y ^ 5`、`z ^ 5` を既に構成された自然数項として扱い、その三項間の線形な加減関係を処理しています。

## 証明の流れ

証明は二段階です。

1. `unfold Fermat5Equation at hEq` により、名前付き述語を生の等式 `x ^ 5 + y ^ 5 = z ^ 5` へ戻す。
2. `omega` がその等式から `z ^ 5 - y ^ 5 = x ^ 5` を導く。

概念的には、`hEq` からまず `y ^ 5 ≤ z ^ 5` が得られ、その範囲で自然数減算が通常の差として機能するため、加法項を除去できます。実装はこの中間不等式を明示せず、`omega` にまとめて委ねています。

## Lean 固有の処理

### 自然数減算

`ℕ` の減算では、例えば `3 - 5 = 0` です。そのため、整数で使う「両辺から同じ項を引く」という説明をそのまま Lean の自然数へ持ち込むと危険です。

この補題が成立するのは、仮定が

```lean
x ^ 5 + y ^ 5 = z ^ 5
```

を与え、右辺が `y ^ 5` 以上であることまで含意するからです。

### `unfold` の対象指定

```lean
unfold Fermat5Equation at hEq
```

はゴールではなく仮定 `hEq` のみを展開します。ゴール側には `Fermat5Equation` が現れていないため、この局所展開で十分です。

### `omega` の適用範囲

冪指数は固定値5ですが、`omega` が二項定理や冪の性質を証明しているわけではありません。各冪項を原子的な自然数式として見て、

```text
A + B = C  ⟹  C - B = A
```

という自然数算術を解いています。

## 冗長・重複箇所

証明は非常に短く、実装上の明白な重複はありません。

ただし、同種の「加法等式から自然数差分へ移す」補題がリポジトリ内に多数存在するなら、一般補題を利用する余地があります。例えば `a + b = c` から `c - b = a` を得る処理を標準補題で記述すれば、`omega` への依存を減らせる可能性があります。

現時点では、リポジトリ全体で同型証明が何件あるかを調査していないため、重複であるとは断定しません。

## 最適化候補

### 可読性重視の明示証明

`omega` 一行は堅牢で簡潔ですが、自然数減算の発動条件を読者へ見せるなら、標準補題を使った明示証明も候補です。

概念上は次の形です。

```lean
unfold Fermat5Equation at hEq
omega
```

を、加法等式の向きを整えたうえで `Nat.add_sub_cancel_left` 系または等式からの書き換えへ置き換えます。ただし、利用する正確な Mathlib 補題名と向きは未検証です。

### tactic 依存の縮小

この局所補題だけを見れば、大規模 tactic の代わりに自然数減算の基本補題で閉じられる可能性があります。一方、ファイル全体が既に `omega` を多数使用するなら、import 削減効果はありません。最適化判断はモジュール全体の利用状況を見て行うべきです。

### API 境界の維持

入力を生の等式へ変更せず、`Fermat5Equation` を受け取る現在の型は、入口 API の一貫性という点でよく設計されています。この部分は維持する価値があります。

## 必要な Mathlib import と最適化候補

standalone は `import Mathlib` を使用しているため、現行環境でこの証明が成立することはリポジトリのビルド成果により確認されています。

この補題が必要とする主要機能は次です。

- 自然数と自然数減算
- 冪記法
- `unfold`
- `omega` tactic

import 最小化では、少なくとも `omega` を提供する Mathlib tactic モジュールと、自然数の基本定義・冪を提供するモジュールが必要です。候補として `Mathlib.Tactic.Omega` が考えられますが、それだけで必要なすべてが推移的に入るかは未検証です。

監査は小さな一時ファイルで `#min_imports` または候補 import を試し、clean build で確認すべきです。本刊行では Lean ビルドを実行していないため、具体的な最小 import を確定事項とはしません。

## Comparator challenge 化

この補題は小規模 Comparator challenge に適しています。

理由は、主張が短い一方で、次の区別を正しく扱う必要があるからです。

- 整数減算と自然数減算の差
- `omega` による自動証明
- 標準補題による明示証明

## 次に読むべき定理

次は `DkMath.FLT.Five.right_lt_of_fermat5Equation` を読むのが自然です。

`fifth_sub_eq_of_add_eq` は第五冪の差を得ますが、後続で gap `z-y` を正の自然数として扱うには `y < z` が必要です。`right_lt_of_fermat5Equation` は `0 < x` とフェルマー方程式からその厳密不等式を導き、続く `gap_pos_of_fermat5Equation` の直接入力になります。

## 根拠と推論の区別

宣言の型、二行の証明、`Fermat5Equation` への直接依存、`unfold` と `omega` の使用は Lean ソースから直接確認できます。

`omega` が冪項を原子的な自然数項として扱うという説明は tactic の適用されている算術形に基づく解説です。標準補題による置換案、最小 import、リポジトリ全体での重複可能性は未検証の最適化提案であり、確定事項ではありません。
