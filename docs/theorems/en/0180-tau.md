# 0180 — `tau`

## Lean type

```lean
/-- Short public name for the distinguished norm-five element `2+φ`. -/
abbrev tau : GoldenInt := goldenTau
```

This is neither a `theorem` nor a `def`, but an `abbrev`. It gives the distinguished ramifier `goldenTau`, defined in 0178, the shorter public name `tau`, closer to ordinary mathematical notation.

## Mathematical statement and meaning of the declaration

Declaration 0178 defines

```lean
def goldenTau : GoldenInt := ⟨2, 1⟩
```

and a coordinate pair `⟨a,b⟩ : GoldenInt` represents $a+b\varphi$. Therefore

$$
goldenTau=2+\varphi.
$$

The present declaration merely introduces the shorter name

$$
\tau:=2+\varphi.
$$

It does not construct a new golden integer or prove a new mathematical property.

The surrounding development proves further that

$$
\tau=\varphi\sqrt5,
$$

and

$$
N(\tau)=5.
$$

Thus `tau` is not an arbitrary cosmetic alias: it exposes the short mathematical name of the norm-five ramified factor that appears in the exceptional five-adic branch of the FLT5 development.

Because this is an `abbrev`, `tau` and `goldenTau` are not merely connected by an equality theorem; `tau` is a transparently reducible alias for the same implementation.

## Proof / construction flow

There is no proof script.

1. `goldenTau` has already been constructed as `⟨2,1⟩` in 0178.
2. The same value is assigned the short name `tau`.
3. `abbrev` exposes the alias more transparently than an ordinary `def`.
4. Subsequent theorems may use `goldenTau` or `tau` for the same mathematical object.

No additional mathematical construction is introduced.

## Lean-specific processing

`abbrev` is treated as a reducible alias and is generally more transparent to elaboration and definitional reduction than an ordinary `def`.

Here

```lean
tau
```

is not intended to introduce a separate opaque constant. Lean can readily unfold it to

```lean
goldenTau
```

when required.

Consequently, existing theorems written using `goldenTau` do not require a large layer of bridge lemmas merely because the shorter public name `tau` exists.

The cost is an expanded API surface: both names can appear in user code, diagnostics, and pretty-printed terms, so the library should ideally make clear which one is canonical.

## Redundancy and duplication

This declaration is intentionally an alias, so it is completely redundant in value with 0178 `goldenTau`:

```lean
goldenTau
```

and

```lean
tau
```

refer to the same `GoldenInt`.

It also repeats exactly the alias pattern used in 0179:

```lean
abbrev sqrtFiveElement : GoldenInt := goldenSqrtFive
```

This is API-level duplication rather than mathematical duplication. It is reasonable if the library intentionally separates internal implementation names `goldenTau` / `goldenSqrtFive` from shorter mathematics-oriented public names `tau` / `sqrtFiveElement`. If downstream code effectively uses only one side, however, the extra alias may simply enlarge the public surface.

## Optimization candidates

1. Keep the current alias layer and explicitly document `goldenTau` as the internal canonical name and `tau` as the public one.
2. Rewrite downstream theorems toward `tau`, making the shorter name the primary public API.
3. Remove the alias if it is rarely used and standardize entirely on `goldenTau`.
4. Make `tau` the canonical definition and demote `goldenTau` to an alias.
5. Apply one consistent naming policy to both 0179 `sqrtFiveElement` and 0180 `tau`.
6. In a generic quadratic-order / ramified-prime API, bundle the distinguished element together with its public-facing notation.

Because this is a one-line `abbrev`, optimization concerns API consistency, discoverability, and canonical naming rather than proof performance.

It is small but suitable as a Lean-library-design comparator.

Useful comparison criteria include:

- definitional transparency

- names appearing in diagnostics and pretty printing

- amount of downstream rewriting

This is not a challenge about mathematical correctness, but about `abbrev`, `def`, notation, and canonical naming in Lean library design.
