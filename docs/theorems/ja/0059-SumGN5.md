# 0059 — `SumGN5`

## 1. Lean の型

```lean
def SumGN5 (u v : ℕ) : ℕ :=
  if v ≤ u then
    (u - v) ^ 4 +
      3 * (u - v) ^ 3 * v +
      4 * (u - v) ^ 2 * v ^ 2 +
      2 * (u - v) * v ^ 3 +
      v ^ 4
  else
    (v - u) ^ 4 +
      3 * (v - u) ^ 3 * u +
      4 * (v - u) ^ 2 * u ^ 2 +
      2 * (v - u) * u ^ 3 +
      u ^ 4
```

`SumGN5` は定理ではなく自然数値を返す定義である。二つの自然数 `u`,`v` に対し、和 `u+v` に対応する第五冪和の residual を与える。

## 2. 数学的主張

この定義の数学的実体は、対称多項式

$$
\frac{u^5+v^5}{u+v}
= u^4-u^3v+u^2v^2-uv^3+v^4
$$

を自然数だけで表現したものである。ただし右辺には負の交差項があるため、そのままでは `ℕ` の式として扱いにくい。そこで `u≥v` と `v>u` に分け、非負差 `u-v` または `v-u` を使う正係数表示へ変形している。

`v ≤ u` なら `d=u-v` と置いて、

$$
\operatorname{SumGN5}(u,v)
= d^4+3d^3v+4d^2v^2+2dv^3+v^4.
$$

反対側では `d=v-u` とし、`u`,`v` を交換した同型の式を使う。したがって piecewise なのは数学的非対称性ではなく、自然数上で符号付き減算を避けるための実装上の表現差である。

## 3. 証明全体での役割

前段の difference orientation では第五冪差を

$$
(w-v)\,GN5(w-v,v)=u^5
$$

と分解する。一方 sum orientation では第五冪和

$$
u^5+v^5=w^5
$$

を

$$
(u+v)\,SumGN5(u,v)=w^5
$$

へ分解する必要がある。`SumGN5` はこの和側 residual を自然数として与え、difference / sum の二方向を共通の exact five-adic packet へ送るための橋となる。

生成済み standalone ソースの節コメントも、`SumGN5` を「positive natural quotient `(u^5+v^5)/(u+v)`」と説明し、piecewise 定義は `Nat` で signed subtraction を避けるためだけのものだと明記している。

## 4. 直接依存する定義・補題

直接のユーザー定義依存はない。Lean 標準の `ℕ`、順序 `≤`、自然数減算 `Nat.sub`、加算・乗算・冪、および `if ... then ... else ...` のみで定義されている。

数学的な背景としては、既刊 0006 `GN5` と対になる residual であり、0052 `SignedBranchAOrientation` の `sumGap` 側を後続の five-adic 層へ送るために導入される。

## 5. 定義の流れ

1. `v ≤ u` を判定する。
2. 真なら非負差 `u-v` を局所座標として正係数多項式を評価する。
3. 偽なら `u ≤ v` が成立する側へ移り、非負差 `v-u` を使って同じ対称 residual を評価する。
4. 後続定理 `add_mul_sumGN5_eq_add_pow_five` が両枝を展開し、いずれも `(u+v)*SumGN5 u v = u^5+v^5` になることを証明する。

## 6. Lean 固有の処理

最重要点は `Nat.sub` の切り詰め減算である。`u-v` と `v-u` の両方を無条件に多項式へ混ぜると、数学的な符号付き差とは異なる挙動になる。そこで順序判定を先に行い、必ず非負側の差だけを使う。

この設計により定義域・値域を `ℕ` のまま保てる。後段の `padicValNat`、自然数整除、正値証明とも相性がよい。

## 7. 冗長・重複箇所

二枝は `u` と `v` を交換したほぼ同一の式であり、構文上は重複が大きい。ただし、この重複は自然数減算の安全条件を型の近くに露出させるという監査上の利点もある。

また数学的には単一の交代符号多項式で書けるため、`ℤ` 上で residual を定義して非負性を証明し `ℕ` へ戻す設計も可能である。ただしその場合、cast と非負性の補題が増える。

## 8. 最適化候補

候補は三つある。

- 現状維持：二枝を明示し、`Nat` の安全性と後段の正値性を優先する。
- 共通 helper：`d,a` に対する `d^4+3*d^3*a+4*d^2*a^2+2*d*a^3+a^4` を局所定義し、二枝の重複を減らす。
- `ℤ` の対称多項式を正本にする：数学的形は最も簡潔だが、five-adic 自然数層との境界変換が増える。

博物館としては現状の piecewise 定義は理由が明確であり、単純なコード短縮だけを目的に変更する価値は小さい。

## 9. 必要 Mathlib import と import 最適化候補

確認できた生成済み `Flt5DkMath/FLT5StandAlone.lean` はファイル全体で `import Mathlib` を使用している。元の分割モジュール `SignedFiveAdic.lean` の正確な import 行は、この生成 artifact だけからは確定できない。

`SumGN5` 定義単体が必要とする機能は自然数演算・順序・冪・条件式に限られるため、`import Mathlib` は明らかに過大であり、より小さい `Mathlib.Data.Nat.*` 系または Lean core 寄りの import へ縮小できる可能性が高い。ただし具体的最小 import 名は未ビルドの推測であり、本記事では確定事項としない。

直後の `add_mul_sumGN5_eq_add_pow_five` まで同一モジュールで扱うなら `ring` tactic が必要になるため、その分の Mathlib import は残る。
