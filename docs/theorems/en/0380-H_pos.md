# 0380 `H_pos`

## Declaration kind

`theorem`

Inside the `GoldenZeroSectorDescentPacket` namespace, this lemma extracts positivity of the quartic factor `goldenFifthSndFactor` from the stored fifth-power representation and positivity of its fifth root.

## Lean code

```lean
theorem H_pos (p : GoldenZeroSectorDescentPacket) :
    0 < goldenFifthSndFactor p.base.fst p.base.snd := by
  rw [p.H_eq]
  exact pow_pos (by exact_mod_cast p.D_pos) 5
```

## Lean type

With the namespace made explicit, its conceptual type is

```lean
GoldenZeroSectorDescentPacket.H_pos :
  (p : GoldenZeroSectorDescentPacket) →
    0 < goldenFifthSndFactor p.base.fst p.base.snd
```

The coordinates `p.base.fst` and `p.base.snd` of `p.base : GoldenInt` are integers, and `goldenFifthSndFactor p.base.fst p.base.snd : ℤ`. Hence the final `<` is the order on integers.

The packet root parameter, however, is `p.D : ℕ`, together with the field

```lean
p.D_pos : 0 < p.D
```

so the proof transports this positivity fact to `ℤ` before applying positivity of powers.

## Mathematical statement

0376 `GoldenZeroSectorDescentPacket` stores

$$
H(r,s)=D^5,
\qquad D>0,
$$

where

$$
r=p.base.fst,
\qquad
s=p.base.snd,
$$

and

$$
H(r,s)=\operatorname{goldenFifthSndFactor}(r,s).
$$

Since the fifth power of a positive integer is positive, one immediately obtains

$$
H(r,s)=D^5>0.
$$

The Lean theorem exposes this elementary mathematical consequence as part of the packet API.

## Role in the overall proof

The zero-sector descent needs more than a bare fifth-power equality. The factors involved in the descent must be known to be nonzero, and in several later arguments their signs must be controlled.

0378 `snd_ne_zero` establishes

$$
s\ne0,
$$

for the second coordinate, while 0379 `snd_natAbs_eq` gives the exact magnitude formula

$$
|s|=5t^5.
$$

The present `H_pos` theorem supplies the corresponding order information for the quartic factor:

$$
H(r,s)>0.
$$

Thus, among the two principal factors

$$
s
\quad\text{and}\quad
H(r,s),
$$

it certifies that the `H` side is nondegenerate and has positive sign.

This information can later be used when removing absolute values, inferring positivity of factors from product identities, and constructing natural-number witnesses for fifth-power splitting.

In the portion of the canonical source checked for this entry, this descent-packet version of `H_pos` is not used directly by the immediately following `five_not_dvd_H`; that theorem extracts a separate divisibility property mainly from `H_eq`, `five_not_dvd_norm`, and the congruence between `goldenFifthSndFactor` and the norm square. Thus `H_pos` is best viewed as a reusable positivity API for the later descent chain rather than as a helper dedicated only to the next theorem.

## Proof flow

1. Rewrite the quartic factor in the goal using `p.H_eq`.

   ```lean
   rw [p.H_eq]
   ```

   The goal is conceptually reduced to

   ```lean
   0 < (p.D : ℤ) ^ 5
   ```

2. `p.D_pos : 0 < p.D` is a positivity statement in `ℕ`. Transport it to the integers with

   ```lean
   by exact_mod_cast p.D_pos
   ```

   obtaining the fact

   ```lean
   (0 : ℤ) < p.D
   ```

3. Apply `pow_pos` to conclude that the fifth power of this positive integer is positive:

   ```lean
   pow_pos (by exact_mod_cast p.D_pos) 5
   ```

Thus the proof is the direct chain

$$
0<D
\Longrightarrow
0<D^5
\Longrightarrow
0<H(r,s).
$$

## Lean-specific processing

### `rw [p.H_eq]`

`H_eq` is a dependent projection stored in the packet. Writing `p.H_eq` selects the equality attached to the current packet and uses it directly as a rewrite rule.

This is significant architecturally: the proof never unfolds the polynomial definition of `goldenFifthSndFactor`. It works entirely through the packet contract and therefore preserves the intended abstraction boundary.

### `exact_mod_cast`

The field `p.D_pos` has type

```lean
0 < p.D
```

in `ℕ`, whereas after rewriting by `H_eq` the right-hand side is `(p.D : ℤ) ^ 5`. Consequently `pow_pos` needs the integer fact

```lean
(0 : ℤ) < (p.D : ℤ)
```

and `exact_mod_cast` handles this order-preserving coercion from naturals to integers.

### `pow_pos`

This general positivity lemma states that a positive base has a positive natural-number power.

The fact that the exponent is specifically odd is not essential here. Since the base `D` itself is positive, the same argument works for any positive power.

## Redundancy and duplication

The proof consists of only two lines and contains essentially no mathematical redundancy.

One possible stylistic expansion would be

```lean
have hDpos : (0 : ℤ) < p.D := by
  exact_mod_cast p.D_pos
exact pow_pos hDpos 5
```

which gives the casted positivity fact a name. This may help if the same cast is reused repeatedly nearby, but for this isolated theorem it would increase code size without adding much clarity.

Also, the short name `H_pos` can occur for another packet type or namespace in the standalone development. Documentation and searches should therefore keep the fully qualified name `GoldenZeroSectorDescentPacket.H_pos` in mind. Namespace resolution makes this harmless in Lean itself.

## Optimization candidates

1. **Keep the current proof as the default.**

   Rewriting by `H_eq`, casting `D_pos`, and finishing with `pow_pos` is already close to minimal and preserves abstraction.

2. **Factor out integer positivity of `D` if it is repeatedly needed.**

   If later proofs repeatedly require `(0 : ℤ) < p.D`, one could introduce a helper such as

   ```lean
   theorem D_int_pos (p : GoldenZeroSectorDescentPacket) :
       (0 : ℤ) < p.D := by
     exact_mod_cast p.D_pos
   ```

   The checked source for this entry does not establish that the repetition is large enough to justify such an API, so this remains only a candidate.

3. **Provide an `H_ne_zero` derivative if useful.**

   The present theorem immediately implies

   ```lean
   theorem H_ne_zero (p : GoldenZeroSectorDescentPacket) :
       goldenFifthSndFactor p.base.fst p.base.snd ≠ 0 :=
     ne_of_gt p.H_pos
   ```

   Such a semantic helper may be worthwhile if downstream arguments frequently need only nonzeroness.

4. **Avoid polynomial expansion.**

   Proving positivity by unfolding `goldenFifthSndFactor` and attacking the resulting polynomial with `ring` or `nlinarith` would be unnecessarily expensive and would discard the stronger stored invariant $H=D^5$. The current proof is structurally preferable.

**Yes. It is suitable as a small invariant-rewrite / cast / positivity challenge.**

The essential challenge consists of three steps:

1. rewrite with the packet field `H_eq` in the correct direction,
2. transport `D_pos : 0 < D` from `ℕ` to `ℤ`,
3. close the fifth-power positivity goal with `pow_pos`.

The mathematics is elementary, but the problem tests an important Lean boundary: moving an order fact about a natural-number witness into an integer polynomial equality.
