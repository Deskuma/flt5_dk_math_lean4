# 0007 — `GN5_eq_homogeneous_cyclotomic`

> 本文書は日本語正本です。英語版は本正本からの対応翻訳です。

## Lean の型

```lean
theorem GN5_eq_homogeneous_cyclotomic (g y : ℕ) :
    GN5 g y =
      (g + y) ^ 4 + (g + y) ^ 3 * y + (g + y) ^ 2 * y ^ 2 +
        (g + y) * y ^ 3 + y ^ 4 := by
  unfold GN5
  ring
```

完全修飾名は `DkMath.FLT.Five.GN5_eq_homogeneous_cyclotomic` です。

## 数学的主張

`GN5 g y` は、第五冪差の標準的な斉次因子

$$
z^4+z^3y+z^2y^2+zy^3+y^4
$$

へ $z=g+y$ を代入した多項式と一致します。すなわち、

$$
GN5(g,y)=(g+y)^4+(g+y)^3y+(g+y)^2y^2+(g+y)y^3+y^4
$$

です。

標準恒等式

$$
z^5-y^5=(z-y)(z^4+z^3y+z^2y^2+zy^3+y^4)
$$

で $g=z-y$、したがって $z=g+y$ と置いたとき、右側の次数4因子が `GN5 g y` になります。

## 証明全体での役割

前号で `GN5` は正係数の展開形として定義されました。本定理は、その展開形が恣意的な補助多項式ではなく、第五冪差の標準的な斉次巡回因子そのものであることを固定します。

この同一視により、後続では次の二つの視点を使い分けられます。

- 展開形：gap $g$ や素数 $5$ を因子として取り出し、合同式・整除性を読む。
- 標準因子形：第五冪差の因数分解との数学的意味を読む。

直接には後続の各補題が必ず本定理を呼び出すわけではありません。実装では `GN5` を直接展開して証明する補題も多くあります。しかし、文書化・監査・数学的解釈において、本定理は `GN5` と古典的因子分解を結ぶ基準点です。

## 直接依存する定義・補題

プロジェクト内の直接依存は次の一つです。

- `DkMath.FLT.Five.GN5`

証明手段として Mathlib の多項式正規化 tactic `ring` に依存します。

数学的には二項展開と可換半環上の多項式恒等式だけを使用し、FLT5 方程式、正値性、互いに素条件には依存しません。

## 証明の流れ

証明は二段階です。

1. `unfold GN5` により左辺を定義された展開多項式へ置き換える。
2. `ring` により両辺を可換半環の正規形へ変換し、一致を確認する。

`ring` が確認する内容は、右辺の各 $(g+y)^k$ を展開すると係数が

$$
1,\ 5,\ 10,\ 10,\ 5
$$

へ集約され、`GN5` の定義と一致することです。

## Lean 固有の処理

`ring` は具体的な自然数値を計算する tactic ではなく、加法・乗法・冪からなる多項式式を正規化して等式を証明します。ここでは変数型が `ℕ` ですが、証明の本質は自然数特有ではなく、可換半環で成立する恒等式です。

`unfold GN5` が必要なのは、`ring` に左辺の定義内部を見せるためです。次の形も候補になります。

```lean
  simp only [GN5]
  ring
```

ただし現在の二行証明は意図が明快で、変更の必要性はありません。

## 冗長・重複箇所

`GN5` の定義と本定理の右辺は同じ多項式の異なる表示なので、式の情報としては重複しています。しかし、この重複は役割を持ちます。

- 定義は後続の gap 分解・5進分解に適した展開座標を提供する。
- 本定理は標準巡回因子との意味論的対応を提供する。

したがって、本定理を削除して定義だけにすることは可能でも、API の説明力と監査可能性を失います。

## 最適化候補

本証明はすでに短く、実行性能上の最適化余地は小さいです。設計上の候補には次があります。

- より一般の可換半環上で多項式恒等式を証明し、自然数版を特殊化する。
- 標準因子側を別の定義として名前付けし、`GN5` との橋として本定理を置く。
- 後続補題が標準因子形を必要とする場合、本定理を rewrite API として明示利用する。

ただし、一般化は import と型推論を重くする可能性があり、現在の局所的な自然数 API の方が簡潔です。これは未検証の設計提案です。

## 必要 Mathlib import と import 最適化候補

現在の standalone は `import Mathlib` を使用しています。本定理が必要とする中心機能は次です。

- 自然数の加法・乗法・冪
- `ring` tactic

厳密な最小 import は今回検証していません。候補を調べるには、定義 `GN5` と本定理だけを一時ファイルへ置き、`#min_imports` または段階的 import 削減を行ったうえで clean build する必要があります。

`Mathlib.Tactic` は `ring` を提供する広い候補ですが、最小とは限りません。この点は推測です。

## Comparator challenge 化

Comparator challenge として良好です。短いながら、次の証明戦略を比較できます。

- `unfold GN5; ring`
- `simp [GN5]; ring`
- `ring_nf` を用いた正規化
- 個別の二項展開補題と算術書き換えによる手動証明

評価点は、証明長だけでなく、定義変更への耐性、エラーメッセージの読みやすさ、一般化可能性です。標準解としては現在の `unfold GN5; ring` が最も直接的です。

## 次に読むべき定理

次は `DkMath.FLT.Five.GN5_eq_gap_mul_add_five_mul_y_pow_four` を読みます。

本定理が `GN5` の標準因子としての意味を固定したのに対し、次の定理は展開形から gap $g$ をまとめ、

$$
GN5(g,y)=g\,A(g,y)+5y^4
$$

という形を得ます。これは $GN5(g,y)\equiv 5y^4\pmod g$ を読み取る最初の整除性インターフェースです。

## 根拠と推論の区別

Lean の型、証明本体、`GN5` の定義、次に並ぶ gap 分解定理はリポジトリ内ソースに直接基づきます。一般の可換半環への拡張、最小 import、後続 API の再構成案は本稿の分析であり、Lean ビルドによる検証は行っていません。
