# 0035 — `Body5`

## 宣言

```lean
def Body5 (g y : ℕ) : ℕ :=
  g * GN5 g y
```

## Lean の型

`Body5` は二つの自然数 `g`, `y` を受け取り、自然数を返す定義です。

```lean
Body5 : ℕ → ℕ → ℕ
```

命題を返す定理ではなく、既存の積 `g * GN5 g y` に意味のある名前を与える計算可能な関数です。

## 数学的主張

定義そのものが表す量は、gap $g$ と第五巡回因子 `GN5(g,y)` の積です。

$$
Body5(g,y)=g\,GN5(g,y).
$$

既に証明済みの第五冪差分解により、この積は次の量に一致します。

$$
Body5(g,y)=(g+y)^5-y^5.
$$

ただし後者は `Body5` の定義だけから得るのではなく、直後の定理 `body5_eq_add_pow_sub` が証明します。

## 証明全体での役割

`Body5` は Branch B 層における意味付けされた略記です。これまで頻出した

```lean
g * GN5 g y
```

を、第五冪差全体を表す一つの対象として扱えるようにします。

元の Fermat 方程式で $g=z-y$ と置けば、

$$
Body5(z-y,y)=z^5-y^5=x^5
$$

となります。したがって後続の clean-channel、完全第五冪排除、valuation 議論では、積の内部形を毎回展開せず `Body5` を境界 API として利用できます。

この定義は新しい数学的情報を加えませんが、証明の語彙を「積」から「第五冪 body」へ引き上げます。

## 直接依存する定義・補題

### `GN5`

```lean
def GN5 (g y : ℕ) : ℕ :=
  g ^ 4
    + 5 * g ^ 3 * y
    + 10 * g ^ 2 * y ^ 2
    + 10 * g * y ^ 3
    + 5 * y ^ 4
```

`Body5` の唯一のローカル依存です。

### 自然数の乗法

`g * GN5 g y` を構成するため、自然数上の乗法を使います。

### 関連する先行補題

定義本体は補題を呼びませんが、意味を保証する先行定理は

```lean
add_pow_five_sub_eq_mul_GN5
```

です。

$$
(g+y)^5-y^5=g\,GN5(g,y).
$$

## 証明の流れ

`def` なので証明スクリプトはありません。Lean は右辺をそのまま定義値として登録します。

1. 入力 `g`, `y : ℕ` を受け取る。
2. `GN5 g y` を計算する。
3. その値に `g` を掛ける。
4. 得られた自然数を `Body5 g y` と定義する。

論理的な証明は次号 `body5_eq_add_pow_sub` から始まります。

## Lean 固有の処理

`Body5` は通常の `def` なので、必要に応じて

```lean
unfold Body5
```

または

```lean
simp [Body5]
```

で右辺へ展開できます。一方、`abbrev` ではないため、名前を保ったまま抽象境界として使いやすく、無制限に透過展開されることを意図していません。

引数は curried 形式であり、`Body5 g` は `ℕ → ℕ` 型の部分適用になります。

定義に `@[simp]` 属性は付いていません。これは `Body5` を常に積へ消去せず、後続定理で意味のある名前として保持する設計と整合します。

## 冗長・重複箇所

計算内容は先行コードに繰り返し現れた `g * GN5 g y` と完全に同じです。数学的には冗長ですが、次の理由で有益です。

- 第五冪差全体へ安定した名称を与える。
- 後続 API の型を短くする。
- `GN5` 単体の性質と、gap を含む full body の性質を区別する。
- 実装変更時に積の表現を一箇所へ集約できる。

したがって、これは除去すべき重複ではなく、意図的な意味論的ラッパーです。

## 最適化候補

現行定義は最小であり、計算面の最適化余地はありません。

未検証の API 設計案として、頻出する展開を制御する補題を用意できます。

```lean
@[simp] theorem Body5_eq (g y : ℕ) :
    Body5 g y = g * GN5 g y := rfl
```

しかし `simp` が `Body5` を積へ常時展開すると、抽象名を導入した利点を弱める可能性があります。現在のように必要な箇所だけ `[Body5]` で展開する方が、証明状態を読みやすく保てます。

また、一般指数版 `Body d g y` への抽象化も考えられますが、本開発は指数五の専用 API を明示する方針であり、本記事の根拠から必要性は確認できません。

## 必要 Mathlib import と import 最適化候補

確認済みの standalone artifact は `import Mathlib` を使用しています。しかし `Body5` 自身が必要とするのは、

- `Nat`
- 自然数の乗法
- ローカル定義 `GN5`

だけです。

実際のモジュールでは `GN5` を提供するプロジェクト内 import が本質です。`Body5` 単独のために広い `Mathlib` import は不要と考えられますが、最小 import のビルド検証は行っていません。
