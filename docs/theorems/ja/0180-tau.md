# 0180 — `tau`

## Lean の型

```lean
/-- Short public name for the distinguished norm-five element `2+φ`. -/
abbrev tau : GoldenInt := goldenTau
```

これは `theorem` や `def` ではなく `abbrev` である。0178 で定義された distinguished ramifier `goldenTau` に対して、数学記法に近い短い公開名 `tau` を与える。

## 数学的主張または宣言の意味

0178 では

```lean
def goldenTau : GoldenInt := ⟨2, 1⟩
```

と定義されている。`GoldenInt` の座標 `⟨a,b⟩` を $a+b\varphi$ と読むので、

$$
goldenTau=2+\varphi.
$$

したがって本宣言は

$$
\tau:=2+\varphi
$$

という短い名前を既存の `goldenTau` に与えるだけで、新しい黄金整数を構成したり新しい数学的性質を証明したりするものではない。

0178 の解説および後続 source では、この元について

$$
\tau=\varphi\sqrt5,
$$

$$
N(\tau)=5
$$

が証明される。したがって `tau` は単なる任意の alias ではなく、FLT5 の exceptional five-adic branch で現れる norm-five ramified factor の短い数学名を公開するための alias である。

`abbrev` なので `tau` と `goldenTau` は theorem を介して等しいというより、必要に応じて透明に展開できる同一実装として扱われる。

## 証明全体での役割

0177–0180 は ramified element の導入と公開名整備の小ブロックを形成する。

```lean
def goldenSqrtFive : GoldenInt := ⟨-1, 2⟩
def goldenTau : GoldenInt := ⟨2, 1⟩
abbrev sqrtFiveElement : GoldenInt := goldenSqrtFive
abbrev tau : GoldenInt := goldenTau
```

0177–0178 が具体的な内部名と座標値を固定し、0179–0180 がそれらへ短い public alias を与える。

この alias 層が終わると、source は再び実質的な算術 theorem 群へ戻り、次に

```lean
theorem goldenSqrtFive_sq :
    goldenMul goldenSqrtFive goldenSqrtFive = goldenOfInt 5 := by
  decide
```

を証明する。その後 `goldenNorm_sqrtFive`、`goldenTau_eq_phi_mul_sqrtFive`、`goldenNorm_tau`、`golden_tau_mul_conj`、`exists_goldenTau_factor_of_five_dvd` へ進む。

したがって本宣言は proof core 自体を進めるのではなく、以後の ramified arithmetic を読みやすくする public API 境界として機能する。

## 直接依存する定義・補題

直接依存は非常に小さい。

- `GoldenInt`
- 0178 `goldenTau`

宣言本体は

```lean
abbrev tau : GoldenInt := goldenTau
```

だけなので、新しい lemma、instance、tactic を必要としない。

数学的意味付けではさらに

- 0161 `goldenPhi`
- 0177 `goldenSqrtFive`
- 0178 `goldenTau`

と関係し、後続 theorem により

$$
\tau=\varphi\sqrt5
$$

という形が明示される。

## 証明または構築の流れ

proof script は存在しない。

1. 0178 で `goldenTau` が `⟨2,1⟩` として既に構成されている。
2. その値を変更せず `tau` という短名を与える。
3. `abbrev` により通常の `def` より透明な alias として公開する。
4. 後続の theorem 群は必要に応じて `goldenTau` または `tau` を同じ数学対象として扱える。

数学的構築は追加されない。

## Lean 固有の処理

`abbrev` は reducible な別名として扱われ、通常の `def` よりも elaboration や definitional reduction で展開されやすい。

ここでは

```lean
tau
```

が独立した opaque な constant を増やすのではなく、必要に応じて

```lean
goldenTau
```

へ透明に展開される。

そのため、既存 theorem が `goldenTau` を使っていても `tau` を導入するための bridge theorem を別途大量に用意する必要がない。

一方で `abbrev` は API の表示名を増やすので、proof term やエラーメッセージでどちらの名前が現れるか、canonical name をどちらとみなすかは library design 上の判断点になる。

## 冗長・重複箇所

本宣言は意図的な alias なので、値の意味では 0178 `goldenTau` と完全に重複する。

```lean
goldenTau
```

と

```lean
tau
```

は同じ `GoldenInt` を指す。

また 0179

```lean
abbrev sqrtFiveElement : GoldenInt := goldenSqrtFive
```

と全く同じ alias pattern を繰り返している。

この重複は数学的な重複ではなく API naming の重複である。内部実装名 `goldenTau` と、数学記法に近い公開名 `tau` を分離する方針なら合理的だが、下流で片方しか使わないなら surface area を増やすだけになる可能性もある。

## 最適化候補

1. 現行の alias 層を維持し、`goldenTau` を内部 canonical 名、`tau` を public 名と明示する。
2. downstream theorem 群を `tau` 側へ寄せ、短い公開名を主 API とする。
3. `tau` がほぼ使われていないなら alias を削除し `goldenTau` に統一する。
4. 逆に `tau` を canonical definition にして `goldenTau` を alias へ降格させる。
5. 0179 `sqrtFiveElement` と合わせて alias naming policy を明文化する。
6. 一般 quadratic order / ramified-prime API へ抽象化し、distinguished element とその public notation を bundle する。

局所的には一行の `abbrev` なので、最適化の焦点は proof performance ではなく API の一貫性、discoverability、canonical naming にある。

## 必要 Mathlib import と import 最適化候補

本 `abbrev` 単独は `GoldenInt` と `goldenTau` が利用可能なら追加の Mathlib theorem や tactic を必要としない。

standalone artifact 全体は `import Mathlib` を利用しているが、本宣言だけを理由に広い import は不要である。実際の最小 import は `GoldenOrder` の上流定義や後続 theorem 群に支配される。

今回は Lean build を行わないため、正確な最小 import 集合は未検証であり、import 削減は最適化候補としてのみ扱う。

## Comparator challenge 化の可否

小さいが可能である。比較候補は、

- `abbrev tau := goldenTau`
- `def tau := goldenTau`
- alias を設けず `goldenTau` に統一
- `tau` を canonical definition とし `goldenTau` を alias にする
- `tau` を notation / scoped notation として提供する

である。

比較軸は、

- definitional transparency
- unfolding / simp の挙動
- エラーメッセージや pretty printer に現れる名前
- API discoverability
- downstream theorem の書き換え量
- public name と internal name の役割分離

である。

数学的内容を比較する challenge ではなく、Lean library design における `abbrev`、`def`、notation、canonical naming の比較課題として適している。
