# 0380 `H_pos`

## 宣言種別

`theorem`

`GoldenZeroSectorDescentPacket` namespace 内で、packet が保持する quartic factor `goldenFifthSndFactor` が正であることを、保存済みの fifth-power 表現と fifth root の正値性から取り出す補題である。

## Lean コード

```lean
theorem H_pos (p : GoldenZeroSectorDescentPacket) :
    0 < goldenFifthSndFactor p.base.fst p.base.snd := by
  rw [p.H_eq]
  exact pow_pos (by exact_mod_cast p.D_pos) 5
```

## Lean の型

namespace を展開すると、型は概念的に

```lean
GoldenZeroSectorDescentPacket.H_pos :
  (p : GoldenZeroSectorDescentPacket) →
    0 < goldenFifthSndFactor p.base.fst p.base.snd
```

である。

`p.base : GoldenInt` の二座標 `p.base.fst`, `p.base.snd` は整数であり、`goldenFifthSndFactor p.base.fst p.base.snd : ℤ` である。したがって結論の `<` は整数上の順序である。

一方、packet の root parameter は `p.D : ℕ` で、field

```lean
p.D_pos : 0 < p.D
```

を持つ。証明ではこれを `ℤ` 上の正値性へ cast して用いる。

## 数学的主張

0376 `GoldenZeroSectorDescentPacket` は

$$
H(r,s)=D^5,
\qquad D>0
$$

を保存している。ここで

$$
r=p.base.fst,
\qquad
s=p.base.snd,
$$

かつ

$$
H(r,s)=\operatorname{goldenFifthSndFactor}(r,s).
$$

正の整数 $D$ の第五冪は正なので、ただちに

$$
H(r,s)=D^5>0
$$

を得る。

Lean の theorem は、この単純な数学的事実を packet API として公開するものである。

## 証明全体での役割

zero-sector descent では、単に fifth-power 等式を持っているだけでなく、そこに現れる因子がゼロでないこと、さらに符号が確定していることが重要になる。

0378 `snd_ne_zero` は第二座標について

$$
s\ne0
$$

を与え、0379 `snd_natAbs_eq` は

$$
|s|=5t^5
$$

を与えた。

今回の `H_pos` は quartic factor 側について

$$
H(r,s)>0
$$

を与える。したがって descent packet の主要な二因子

$$
s
\quad\text{と}\quad
H(r,s)
$$

のうち、`H` 側が確実に非退化かつ正符号であることを固定する。

これは後続で絶対値を外したり、積等式から各因子の正値性を推論したり、fifth-power splitting の自然数 witness を構成したりする際の順序情報として利用できる。

ただし、今回確認した正本範囲では、この descent-packet 版 `H_pos` が直後の `five_not_dvd_H` の証明に直接使われているわけではない。`five_not_dvd_H` は主として `H_eq` と `five_not_dvd_norm` を使う別の算術的情報を抽出する。したがって `H_pos` の役割は、直後の一補題専用というより、後段 descent chain に対する正値性 API の整備と見るのが正確である。

## 直接依存する定義・補題

直接依存するプロジェクト内宣言は次である。

- `GoldenZeroSectorDescentPacket`
- `GoldenZeroSectorDescentPacket.H_eq`
- `GoldenZeroSectorDescentPacket.D_pos`
- `goldenFifthSndFactor`

packet の field は

```lean
H_eq :
  goldenFifthSndFactor base.fst base.snd = (D : ℤ) ^ 5

D_pos : 0 < D
```

である。

Mathlib / Lean 側で直接使う主要機能は次である。

- `rw`
- `pow_pos`
- `exact_mod_cast`
- `Nat` から `Int` への coercion

0378 `snd_ne_zero`、0379 `snd_natAbs_eq` には論理的には依存しない。今回の theorem は `H_eq` と `D_pos` の二つだけで閉じている。

## 証明の流れ

1. `p.H_eq` により結論中の quartic factor を fifth power に書き換える。

   ```lean
   rw [p.H_eq]
   ```

   goal は概念的に

   ```lean
   0 < (p.D : ℤ) ^ 5
   ```

   となる。

2. `p.D_pos : 0 < p.D` は自然数上の正値性なので、

   ```lean
   by exact_mod_cast p.D_pos
   ```

   により

   ```lean
   (0 : ℤ) < p.D
   ```

   を得る。

3. `pow_pos` によって正数の第五冪が正であることを示す。

   ```lean
   pow_pos (by exact_mod_cast p.D_pos) 5
   ```

これで

$$
0<D
\Longrightarrow
0<D^5
\Longrightarrow
0<H(r,s)
$$

という一本道の証明が完了する。

## Lean 固有の処理

### `rw [p.H_eq]`

`H_eq` は packet field として保持される dependent projection である。`p.H_eq` と書くことで、現在の packet `p` に束縛された等式をそのまま rewrite rule として用いる。

これにより `goldenFifthSndFactor` の多項式定義を一切展開せず、packet contract のみで証明できる。これは abstraction boundary を維持する良い使い方である。

### `exact_mod_cast`

`p.D_pos` の型は

```lean
0 < p.D
```

であり、これは `ℕ` 上の不等式である。一方、`H_eq` の右辺は `(p.D : ℤ) ^ 5` なので、`pow_pos` が必要とする前提は整数上の

```lean
(0 : ℤ) < (p.D : ℤ)
```

である。

`exact_mod_cast` はこの自然数から整数への順序保存 cast を処理する。

### `pow_pos`

一般の ordered ring / ordered semiring 的な正値性 lemma を使い、底が正なら自然数冪も正であることを与える。

指数が `5` で奇数であることは、この証明では本質ではない。底 $D$ 自体が正なので、任意の正の冪について同じ argument が成立する。

## 冗長・重複箇所

証明は二行であり、実質的な冗長性はほとんどない。

ただし

```lean
exact pow_pos (by exact_mod_cast p.D_pos) 5
```

の内部で `Nat → Int` cast と positivity を同時に処理しているため、同様の cast が後続で繰り返されるなら

```lean
have hDpos : (0 : ℤ) < p.D := by
  exact_mod_cast p.D_pos
```

のような局所名を置く方が読みやすい場合はある。

一方、この theorem 単体では現在の短い形の方が明快であり、局所 lemma を追加するとむしろコード量が増える。

また `H_pos` という名前は同じ standalone 内の別 namespace / 別 packet 型でも現れ得るため、文書や検索では `GoldenZeroSectorDescentPacket.H_pos` と fully qualified name を意識した方がよい。Lean の namespace が衝突を解決しているので、コード上の問題ではない。

## 最適化候補

1. **現状維持が第一候補**

   `H_eq` を rewrite し、`D_pos` を cast して `pow_pos` に渡す構造は最短級であり、抽象化も保たれている。

2. **整数版 `D_pos` helper の共通化**

   後続で `(0 : ℤ) < p.D` が何度も必要になる場合だけ、

   ```lean
   theorem D_int_pos (p : GoldenZeroSectorDescentPacket) :
       (0 : ℤ) < p.D := by
     exact_mod_cast p.D_pos
   ```

   のような helper を用意する余地がある。ただし現時点で繰り返し頻度を十分確認していないため、これは候補に留まる。

3. **`H_ne_zero` の派生 API**

   今回から

   ```lean
   theorem H_ne_zero (p : GoldenZeroSectorDescentPacket) :
       goldenFifthSndFactor p.base.fst p.base.snd ≠ 0 :=
     ne_of_gt p.H_pos
   ```

   を即座に得られる。後続が非零性だけを要求する箇所が多いなら、有用な semantic helper になり得る。

4. **多項式展開は避ける**

   `goldenFifthSndFactor` を `ring` や `nlinarith` で直接正値証明する方向は、この theorem では明らかに過剰である。packet がすでに $H=D^5$ を保存しているため、その invariant を使う現行設計が最も堅い。

## 必要 Mathlib import と import 最適化候補

standalone 正本は `import Mathlib` を使用している。

この theorem 単体で必要になる Mathlib 側の要素は概ね次である。

- 自然数・整数と coercion
- ordered arithmetic
- power positivity (`pow_pos`)
- rewriting (`rw`)
- `exact_mod_cast` tactic

さらに実際の modular file では、プロジェクト側の

- `GoldenZeroSectorDescentPacket`
- `goldenFifthSndFactor`

まで到達する import が必要である。

`exact_mod_cast` を使うため、その tactic を提供する Mathlib module が必要になる。厳密な最小 import 集合は Lean ビルドを行わない条件のため確認していない。したがって `import Mathlib` からの削減は可能性の提示に留める。

## Comparator challenge 化の可否

**可能。小規模な invariant-rewrite / cast / positivity challenge に向く。**

challenge の本質は

1. packet field `H_eq` を適切な向きに rewrite すること、
2. `D_pos : 0 < D` を `ℕ` から `ℤ` に移送すること、
3. `pow_pos` で fifth power の正値性を閉じること、

の三点である。

数学的難度は低いが、Lean では「自然数 witness を整数多項式の等式へ埋め込んだ後に order fact をどう運ぶか」という型境界の扱いを見る良い micro challenge になる。

より難しくするなら `exact_mod_cast` を禁止し、`Int.ofNat_pos.mpr` 等の明示的な cast lemma で証明させる形式が考えられる。ただし使用可能 lemma 名は Mathlib version に依存するため、challenge 化の際には対象環境で確認が必要である。

## 次に読むべき宣言

次は同じ namespace の

```lean
theorem five_not_dvd_H (p : GoldenZeroSectorDescentPacket) :
    ¬ (5 : ℤ) ∣ goldenFifthSndFactor p.base.fst p.base.snd := by
  intro h5H
  apply p.five_not_dvd_norm
  rw [← goldenZeroSectorLift_norm, p.H_eq] at h5H
  ...
```

である。

今回が

$$
H(r,s)>0
$$

という順序情報を抽出したのに対し、次は

$$
5\nmid H(r,s)
$$

という five-adic / divisibility 情報を抽出する段階へ進む。

つまり packet が保持する quartic factor に対して、

$$
\text{positive}
\quad+\quad
\text{5-adically clean}
$$

という二つの性質を順に公開し、後続の coprime fifth-power splitting と strict descent に必要な算術条件を整えていく流れである。
