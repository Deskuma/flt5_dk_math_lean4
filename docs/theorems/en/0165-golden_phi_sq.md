# 0165 — `golden_phi_sq`

## Lean type

```lean
/-- The defining relation of the coordinate order: `φ^2 = φ+1`. -/
@[simp] theorem golden_phi_sq :
    goldenMul goldenPhi goldenPhi = goldenAdd goldenPhi goldenOne := by
  decide
```

This is a `theorem`. It explicitly exposes, on the raw-operation API `goldenMul` / `goldenAdd` / `goldenOne`, the defining relation `φ^2 = φ + 1` satisfied by the generator `goldenPhi` of the golden integer order.

## Mathematical statement and meaning of the declaration

Read an element of `GoldenInt` as

$$
x=a+b\varphi.
$$

Declaration 0161 defines

```lean
def goldenPhi : GoldenInt := ⟨0, 1⟩
```

so `goldenPhi` is exactly the basis element `φ`.

The upstream multiplication is

```lean
def goldenMul (x y : GoldenInt) : GoldenInt :=
  ⟨x.fst * y.fst + x.snd * y.snd,
    x.fst * y.snd + x.snd * y.fst + x.snd * y.snd⟩
```

which is the coordinate multiplication obtained after reducing higher powers with

$$
\varphi^2=\varphi+1.
$$

Substituting `goldenPhi = (0,1)` gives

$$
(0,1)\cdot(0,1)=(1,1),
$$

while `goldenPhi + goldenOne` also gives

$$
(0,1)+(1,0)=(1,1).
$$

Thus this theorem turns the quadratic relation already compiled into the multiplication formula into an explicit public mathematical API fact.

## Role in the overall proof

The `GoldenOrder` development first constructs `GoldenInt` from two integer coordinates, defines raw operations, builds `CommRing GoldenInt`, and then introduces `goldenPhi`, conjugation, and norm.

This theorem is the most direct certificate that the coordinate model is not merely `ℤ × ℤ`, but represents the quadratic order

$$
\mathbb Z[\varphi],\qquad \varphi^2-\varphi-1=0.
$$

The relation is foundational for the declarations that follow: `goldenConj_phi` identifies the conjugate action `φ ↦ 1-φ`, `goldenNorm_phi` proves `N(φ)=-1`, and later unit and unit-classification arguments exploit the arithmetic generated by this quadratic relation.

## Direct dependencies

The main direct dependencies are:

- `GoldenInt`
- `goldenPhi`
- `goldenOne`
- `goldenAdd`
- `goldenMul`

Mathematically, `goldenMul` already incorporates the reduction `φ^2 = φ+1`, so the theorem introduces no new external axiom or algebraic assumption.

Conceptually the dependency chain is

$$
\texttt{goldenPhi},\ \texttt{goldenOne},\ \texttt{goldenAdd},\ \texttt{goldenMul}
\longrightarrow
\texttt{golden\_phi\_sq}.
$$

## Proof / construction flow

The entire proof is

```lean
by
  decide
```

Both sides reduce to concrete `GoldenInt` values, and equality on `GoldenInt` is decidable, so `decide` evaluates the coordinate computation and produces the proof.

Expanded manually, the first coordinate is

$$
0\cdot0+1\cdot1=1,
$$

and the second coordinate is

$$
0\cdot1+1\cdot0+1\cdot1=1.
$$

The result is therefore `(1,1)`, exactly the value of `goldenAdd goldenPhi goldenOne`.

## Lean-specific processing

`decide` proves propositions equipped with a `Decidable` instance by evaluating their decision procedure. Here the equality is between closed concrete values, so Lean can completely evaluate the integer-coordinate computation.

The theorem also carries `@[simp]`. Consequently simp may normalize the raw expression

```lean
goldenMul goldenPhi goldenPhi
```

to

```lean
goldenAdd goldenPhi goldenOne
```

which is precisely the mathematical normalization direction `φ^2 → φ+1`.

It is plausible that sufficient unfolding would make `rfl` work as well, but no Lean build is performed in this museum pass. That possibility is therefore recorded only as an optimization candidate, not as a verified replacement.

## Redundancy and duplication

The definition of `goldenMul` already encodes `φ^2=φ+1`, so the theorem republishes a fact that can be computed directly from the implementation.

This duplication is useful rather than accidental. It prevents later proofs from repeatedly unfolding coordinate multiplication and instead exposes the defining quadratic relation as a named `@[simp]` theorem. In other words, it separates the internal coordinate implementation from the external mathematical API.

## Optimization candidates

Several proof and API designs are worth comparing.

1. Keep the current `by decide`, emphasizing that the theorem is a closed computation.
2. If verified, replace it with `rfl` to emphasize definitional equality.
3. Use `norm_num [goldenPhi, goldenMul, goldenAdd, goldenOne]` to make the evaluation path explicit in the tactic script.
4. Add a standard-notation theorem such as `goldenPhi ^ 2 = goldenPhi + 1`, retaining the raw theorem as an implementation-level bridge.

Option 4 may improve downstream readability, while the current theorem remains particularly transparent as a direct consistency check for the raw coordinate API.

## Required Mathlib imports and import optimization

The standalone artifact uses `import Mathlib`. This theorem itself only needs the upstream `GoldenInt` definitions, integer arithmetic, decidable equality, and `decide`.
