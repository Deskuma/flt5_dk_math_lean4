# 0035 — `Body5`

## Declaration

```lean
def Body5 (g y : ℕ) : ℕ :=
  g * GN5 g y
```

## Lean type

`Body5` is a definition that takes two natural numbers `g` and `y` and returns a natural number.

```lean
Body5 : ℕ → ℕ → ℕ
```

It is not a theorem returning a proposition. It is a computable function that gives the existing product `g * GN5 g y` a meaningful name.

## Mathematical statement

The quantity represented by the definition is the product of the gap $g$ and the fifth cyclotomic factor `GN5(g,y)`.

$$
Body5(g,y)=g\,GN5(g,y).
$$

By the already proved factorization of a fifth-power difference, this product equals

$$
Body5(g,y)=(g+y)^5-y^5.
$$

The latter equality does not follow from the definition alone. It is proved by the immediately following theorem `body5_eq_add_pow_sub`.

## Role in the complete proof

`Body5` is a semantically meaningful abbreviation in the Branch B layer. It allows the repeatedly occurring expression

```lean
g * GN5 g y
```

to be treated as one object representing the entire fifth-power difference.

For the original Fermat equation, setting $g=z-y$ gives

$$
Body5(z-y,y)=z^5-y^5=x^5.
$$

Thus later clean-channel, perfect-fifth-power exclusion, and valuation arguments can use `Body5` as a boundary API without expanding the product at every occurrence.

The definition adds no new mathematical information, but it raises the vocabulary of the proof from an anonymous product to the named “fifth-power body.”

## Direct dependencies

### `GN5`

```lean
def GN5 (g y : ℕ) : ℕ :=
  g ^ 4
    + 5 * g ^ 3 * y
    + 10 * g ^ 2 * y ^ 2
    + 10 * g * y ^ 3
    + 5 * y ^ 4
```

This is the only local dependency of `Body5`.

### Multiplication on natural numbers

Natural-number multiplication is used to form `g * GN5 g y`.

### Related preceding theorem

The definition itself invokes no lemma, but the preceding theorem that supplies its mathematical meaning is

```lean
add_pow_five_sub_eq_mul_GN5
```

$$
(g+y)^5-y^5=g\,GN5(g,y).
$$

## Proof flow

Because this is a `def`, there is no proof script. Lean registers the right-hand side as the definitional value.

1. Receive inputs `g`, `y : ℕ`.
2. Compute `GN5 g y`.
3. Multiply that value by `g`.
4. Define the resulting natural number to be `Body5 g y`.

Logical proof begins with the next article, `body5_eq_add_pow_sub`.

## Lean-specific processing

`Body5` is an ordinary `def`, so it can be expanded when needed by

```lean
unfold Body5
```

or

```lean
simp [Body5]
```

It is not an `abbrev`. This makes it easier to preserve the name as an abstraction boundary rather than treating it as an expression intended for unrestricted transparent expansion.

The arguments are curried, so `Body5 g` is a partially applied function of type `ℕ → ℕ`.

The definition has no `@[simp]` attribute. This agrees with the design goal of retaining `Body5` as a meaningful name instead of always eliminating it into the product.

## Redundancy and duplication

The computational content is exactly the expression `g * GN5 g y`, which already appeared repeatedly in preceding code. It is mathematically redundant but useful for the following reasons.

- It gives a stable name to the complete fifth-power difference.
- It shortens the types of later APIs.
- It separates properties of `GN5` alone from properties of the full body including the gap.
- It centralizes the representation of the product if implementation details later change.

This is therefore intentional semantic wrapping rather than duplication that should be removed.

## Optimization candidates

The current definition is minimal and has no computational optimization to perform.

As an unverified API design option, one could add a controlled expansion lemma.

```lean
@[simp] theorem Body5_eq (g y : ℕ) :
    Body5 g y = g * GN5 g y := rfl
```

However, making this a simplification rule could cause `simp` to erase `Body5` everywhere, weakening the benefit of introducing the abstraction. Explicit expansion with `[Body5]` only where needed may keep proof states more readable.

A general-exponent abstraction such as `Body d g y` is also conceivable, but this development intentionally exposes an exponent-five-specific API, and the evidence in this article does not establish a need for that generalization.

## Required Mathlib imports and import optimization candidates

The verified standalone artifact uses `import Mathlib`. `Body5` itself requires only

- `Nat`,
- multiplication on natural numbers, and
- the local definition `GN5`.

In the actual module, the essential import is therefore the project module that provides `GN5`. A broad `Mathlib` import should not be necessary for this definition alone, but no minimal-import build was performed.
